# Hall Monitor

Someone has to stand in the hallway.

They read the note, check the rules, and point at a door. A harness knocks the
way it knocks on any provider. The guide is allowed to enjoy the job: the
hallway, the two doors, the note, the questions, the house rules, the keys,
and the tape. Preview it with `sbt docsPreview`.

Conversational calls (`POST /v1/chat/completions`) only go to conversational backends. Decision calls (`POST /jev/v1/systemone`) only go to decision backends. The URL picks the kind. Jev does not.

The classifier is its own System One endpoint. It sees the request text, so a PII rule means that text is sent to the classifier before any route is chosen. Point `classifier` at a local System One unless you intend to send that text out. It is not one of the backends, and it is not listed in either models endpoint.

## Run

```bash
sbt "app/run examples/hall-monitor.toml"
```

The file path is the first argument, or `HALL_MONITOR_CONFIG`, or `./hall-monitor.toml`.

| Harness setting | Value |
| --- | --- |
| OpenAI base URL | `http://127.0.0.1:8080/v1` |
| OpenAI model | `hall-monitor`, or a conversational backend id |
| Jev / hexis `baseUrl` | `http://127.0.0.1:8080/jev` |
| API key | the Hall Monitor key (`apiKey` or `apiKeyEnv` at the top of the file) |

A hexis client that leaves its model at `jev-latest` gets a 404 unless that string is a backend id or alias. Set the model to `hall-monitor` to let the router choose, or to a decision backend id.

## Config

TOML, loaded with zio-config (`zio-config-toml`). Put the process keys (`apiKey` or `apiKeyEnv`, limits, `defaultPrefer`) before the first table. A key written after `[listen]` belongs to listen. Adding a model is another `[[backends]]` table. Adding a question is another `[[criteria]]` table: `instructions` is the prompt, and the kind is `noul` (yes and no), `score` (ordered levels), or `choice` (an `[criteria.options]` table on that question). A question does nothing until a `[[rules]]` table names it. The questions page of the guide has the shapes. `[criteria.options]` attaches to the last `[[criteria]]`.

Every secret is either `apiKey` (the token in the file) or `apiKeyEnv` (the name of an environment variable). Set one of them. The same pair is used for the Hall Monitor key, the classifier, and each backend.

Constraints intersect. A PII rule that allows only `local-strong` and `jev-vpc` cannot be widened by a preference for a public model. Preferences only rank inside the models still allowed. `POST /admin/reload` with the bearer token re-reads the file. A bad file keeps the previous policy.

`stream: true` is returned as the upstream event stream, after the upstream body has been buffered. Time to first token is the full completion.

See `examples/hall-monitor.toml`.
